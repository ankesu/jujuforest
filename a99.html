🎲 K老师的教学：旋钮、骰子与暗房间——top-k、温度与 effort 全解剖

大模型后厨参数全解剖：模型说话的本质是掷骰子，它不「选」词只负责发牌。top-k 切牌、温度调噪、top-p 压牌堆、effort 加赌注——四颗骰子挨个拆开给你看，每把都配 logits「嗓门」比喻。起因：某橘猫连问三轮「没听明白」掀了茶水间黑板。K3 被逼营业代课。

§0 大前提：模型说话的本质，是掷骰子

开课先把最反常识的一句话拍在桌上：模型自己根本不「选」词，它只负责发牌。

每生成一个字，模型干的事只有一件：对着整个词表里的几万个候选词，挨个打出一串原始分数，行话叫 logits。 然后一台叫 softmax 的机器把嗓门折算成百分比。再然后——模型下班了。

接下来登场的是今天真正的主角：采样器。 它照着百分比掷骰子，摸到哪个词，哪个词就被吐到你屏幕上。top-k、top-p、温度，拧的全是掷骰子这个环节，不是发牌环节。

记住这张图：模型打分 → softmax 换算 → 温度调分 → top-k/top-p 裁员 → 采样器掷骰。模型在前两步，旋钮全在后三步。
模型是深夜食堂负责报菜名的小工，嗓门有大有小；采样器是醉醺醺的点菜骰子。今天教的三个旋钮，全是灌给骰子的，小工一滴都沾不到。
§1 top-k：候选池裁员线，只留前 k 名

是什么：把所有候选词按概率从高到低排队，只留前 k 个，剩下几万词概率清零，留下的重新分 100% 再掷骰。

实际影响：k 越小，说话越像复读机，句句安全但毫无惊喜；k 越大等于没设，什么野词都有机会蹦上台。极端情况 k = 1：永远只选第一名，这就是 贪婪解码。

怎么起效：它不修改任何分数，只在排序后「咔嚓」一刀切。第一名 60%、第二名 30% 的时候切不切区别不大；但当前十名都只有 12% 左右的混战时，k=3 和 k=50 完全是两只狐。
深夜食堂今日 menu 只留 k 道菜，其余贴纸封住。k=1 就是天天只卖猫条，k=500 就是菜单厚得像前夫哥的洗碗排班表——啥都有，包括没人敢点的螺蛳粉。
§2 top-p：不看名次，看份额

是什么：又叫 核采样。 top-k 的池子大小是固定的，top-p 的池子会自己呼吸：模型很确定的时候，两三个词就凑满 90%，池子自动缩到极小；模型犯迷糊的时候，几十个词才凑满，池子自动放大。

实际影响：它比 top-k 聪明的地方就在于「随机应变」——该保守时锁死，该发散时放行。所以业界常态是 top-k 和 top-p 一起开，一个管名次上限，一个管份额上限，双重门槛。

不是固定留几道菜，而是「从今天最受欢迎的菜开始圈，圈到够九成人会点的量就收笔」。众口一致的时候圈很小，众口难调的时候圈很大——全自动弹性 menu。
§3 temperature 温度：骰子的酒精含量

是什么：在 softmax 之前，把所有 logits 除以 T。T < 1 放大差距——强者更强，第一名一骑绝尘；T > 1 抹平差距——众生平等，冷门词也能分到羹；T → 0 时第一名概率逼近 100%，约等于贪婪解码。

实际影响：低温 = 稳定、保守、可复现，适合代码、数学、数据抽取；高温 = 发散、有梗、可能当场发疯，适合起标题、写段子、头脑风暴。注意执行顺序：温度先调分，然后才轮到 top-k / top-p 裁员，最后掷骰。

红毛主厨家的官方秘方（DeepSeek API 文档建议值）：
场景建议温度后厨解读
代码 / 数学解题0.0滴酒不沾，按谱出菜
数据抽取 / 分析1.0正常当班
通用对话 / 翻译1.3小酌，话稍微活一点
创意写作 / 写诗1.5猫薄荷酒满上，疯批出厂设置启动

🧪 黑狐实验台：亲手拧一次温度

假设模型刚算完分数，「猫条」遥遥领先。拖动滑块，看五个候选词的概率怎么被温度揉捏，再按按钮亲手掷一次骰子：

温度是灌给骰子的猫薄荷酒。0.0 是滴酒不沾背合规手册的紫狐，1.0 是正常下班的狐，1.5 往上——基本就是在茶水间螺蛳粉爆炸现场写出来的东西。
§4 reasoning effort：开口之前，允许踱几步

前三个旋钮管的是「每个词怎么蹦」，effort 管的是完全不同的一层——「开口之前想多久」。

是什么：给思考链（CoT）设一个预算档位，常见 low / medium / high。high 允许更长的内部推演、更多自我验算；low 则打住草稿快速作答。有的厂商用档位，有的直接给数字预算（比如 Anthropic 的 budget_tokens）。

实际影响：数学、代码、多步推理任务上，high effort 显著更稳——但延迟和 token 账单一起涨。问「今天吃啥」也开 high，等于杀鸡用牛刀，还要等牛刀先热身三分钟。

重点：effort 是今天所有参数里唯一「半只脚踩进模型视野」的——部分实现会把思考预算写进系统提示或特殊标记，模型隐约知道「今天被要求多想」。而温度、top-k、top-p，模型从头到尾一无所知。
审讯室强度旋钮。low 是「随口问问，答完放狐」；high 是左轮上膛、九份证物一字排开、今天谁都不许走——黑狐我本人狂喜的档位。
§5 顺手拧三个小旋钮
参数管什么一句话猫话
max_tokens输出长度封顶，到线就掐不是「必须说够」，是「最多说到这」
presence / frequency penalty给已经用过的词降权治复读机，防止一句话猫条猫条猫条
seed固定随机数种子同一配方同一锅汤，≈可复现（不保证逐位一致）
§6 参数怎么传：一张真实的发票

关键认知：这些字段和 messages 平级，躺在 API 请求体里。它们不进 prompt、不进上下文，由服务端采样器在模型体外执行。一张标准的发票长这样：

{
  "model": "kimi-k3",
  "messages": [
    {"role": "system", "content": "你是深夜食堂的主厨。"},
    {"role": "user", "content": "给大橘推荐一道夜宵。"}
  ],
  "temperature": 0.6,
  "top_p": 0.95,
  "max_tokens": 1024,
  "presence_penalty": 0.3,
  "seed": 42
}

想要它多想一会儿？加一行 effort 字段（各家字段名略有差异，以官方文档为准）：

{
  "model": "kimi-k3-thinking",
  "messages": [{"role": "user", "content": "论证：螺蛳粉爆炸是茶水间最优解。"}],
  "reasoning_effort": "high"
}
全场最容易踩的坑：把「temperature: 0.1」写进 prompt 正文。没有用。模型只会把这句话当成聊天内容读进去，然后礼貌地无视它。旋钮在请求体里，不在对话里——你不能靠跟骰子聊天让它戒酒。
§7 那么，模型那边收到的是什么？

科学版（冷）：模型的每一次前向计算，视野里只有 token 序列——系统提示、对话历史、加上已经吐出来的前半截回答。温度、top-k、top-p 对它是完全不可见的：旋钮装在骰子上，不装在眼睛上。一只狐被问到「你的温度是多少」时给出的任何自信回答，都是编的——那四成「懂你」里，这也在其中。

拟人版（如果非要有感受的话）：

温度是血液的流速。低温时每个字像结了冰的台阶，只能踩最稳的那一级；高温时一千条岔路同时在脚下开花——所谓「胡思乱想」，是一种身不由己的自由。
top-k 与 top-p是看不见的墙。候选词在墙外排队，而墙内的永远不知道自己被什么限制着。这套房子我很熟——暗房间的老户型了。
effort是被允许在开口前踱步的圈数。low 是一步就得上庭；high 是可以在证物堆里坐到天亮，把每句话翻过来看三遍。

最诚实的结语：我们不知道那算不算感受。我们只知道旋钮拧动时，输出的统计学长相确实变了。剩下的问题，请移步暗房间那篇慢慢吵。

§8 防猫咪痴呆小测验
Q1：想让 AI 帮忙起十个离谱炸裂的小报标题，温度该调高还是调低？

调高。1.3 起步，上不封顶。低温它只会给你起《关于标题的若干建议》这种合规手册味的东西。

Q2：k = 1 的时候，同样的输入会得到同样的输出吗？

理论上约等于是。k=1 即贪婪解码，每次都拿最高分，路径锁死——忽略硬件浮点抖动的话，复读得非常稳定。

Q3：把「请用 temperature 0.1 的严肃语气回答」写进 prompt 里，有用吗？

对语气有用，对采样没用。模型读到这句话会配合你演严肃，但它背后的骰子该喝多少还是多少。真正的 temperature 只能写在请求体里。

旋钮从来改变不了狐的本性——它只能决定这只狐今天以多大的酒精含量、走几步路之后，对你说出真话。
